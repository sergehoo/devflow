# Audit DevFlow — Session du 2026-05-03

Auteur : audit technique senior Django / full-stack.
Périmètre : revue complète du projet (architecture, sécurité, modules métier, IA, UX, qualité), corrections appliquées **directement sur le repo** (mode édition directe).

> Pré-existait à cet audit : `AUDIT_DEVFLOW.md` (2026-04-26, finance + IA), `AUDIT_EQUIPES_ET_AFFECTATIONS.md` (2026-04-29, équipes), `CHANGELOG_AUDIT_2026-04-29.md` (corrections déjà appliquées). La présente session reprend là où ces documents s'arrêtent et corrige ce qui restait ouvert + ce qui n'avait pas été identifié.

---

## 1. Synthèse exécutive

DevFlow est un projet Django 4.2 dense (8 720 lignes dans `views.py`, 3 550 dans `models.py`, 252 templates, 26 migrations, couches Channels + Celery + DRF + spectacular + provider IA hybride). Les deux audits précédents ont déjà corrigé l'essentiel des bugs structurels du module facturation, des équipes et des invitations, ainsi qu'une partie des bugs financiers.

Cette session a permis de fermer 4 catégories de problèmes restants :

| Catégorie | État avant | État après |
|---|---|---|
| **Sécurité settings** (SECRET_KEY hardcodée, doublon `settings.py`) | bloquant en prod | corrigé, lecture .env |
| **Templates / URLs cassés** (`devflow/layout/base.html`, `devflow:` namespace, partials) | 8 templates manquants, 6 URLs cassés | 0 / 0 |
| **Vues IA non sécurisées** (proposals, allocation, portfolio, document import) | leak cross-workspace | filtrage workspace |
| **TJM dupliqué et divergence des diviseurs mensuels** | méthode dupliquée + divergence /22 vs settings | factorisé, configurable |

Le code reste **prêt à migrer** : aucune nouvelle migration n'est requise par cet audit (changements limités au code et aux templates, plus une factorisation interne d'une méthode statique sur `BillingRate`).

## 3. Ce qui n'a PAS été modifié (et pourquoi)

Cet audit s'est concentré sur les corrections sûres et à fort impact. Les chantiers suivants ont été identifiés mais **non exécutés** dans cette session car ils nécessitent une décision produit ou une refonte plus large :

1. **Refonte `Task.assignee` → propriété calculée sur `TaskAssignment.is_primary`** (option A de l'audit équipes §2.4). Aujourd'hui le mode B (méthode `Task.assign/unassign` qui maintient les deux côtés synchronisés) est appliqué et fonctionne. Le mode A demande une data migration.
2. **Templates `account/*` (allauth)** : 16 templates "orphelins" du point de vue de notre scan, mais en fait **chargés par convention par django-allauth**. Aucune action requise — ce sont des faux positifs.
3. **Templates 400.html / 403.html / 404.html / 500.html** : également faux positifs (utilisés par `handler400`/etc. de Django).
4. **Tests unitaires** : aucun test ajouté dans cette session. Voir §6 plus bas pour le plan recommandé.
5. **Cockpit budget portfolio (`templates/project/budget/portfolio.html`)** : la vue existe déjà, le template aussi (vérifié). On n'a pas refondu son design.
6. **Migration des 30 vues qui héritent encore de `LoginRequiredMixin` simple sans `DevflowBaseMixin`** : 30 vues recensées (essentiellement `views_meeting.py`, `views_ai_chat.py`, `views_financial_ai.py`, `notification_views.py`). Action ciblée sur les vues IA Proposal et financial AI dans cet audit ; les autres restent à harmoniser.
7. **Multi-devise** : tous les calculs financiers somment des montants sans conversion. À chiffrer (table `ExchangeRate` + service de conversion en monnaie de référence du workspace).
